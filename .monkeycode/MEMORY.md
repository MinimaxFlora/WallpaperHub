- Context: Discovered by Agent while implementing the Go wallpaper service
- Category: Build Methods
- Instructions:
  - Regenerate the image manifest with `go run ./cmd/manifest -root . -out manifest.json`. It is idempotent: when image metadata and bytes are unchanged it leaves `manifest.json` untouched, so re-running it cannot create empty commits.
  - Compilation, `go test` and `go vet` must run through managed background terminals per the repository resource-limit rule.
  - The Docker image pins `golang:1.27.1-alpine`, so the toolchain is not downloaded during container builds.
  - TLS is not handled by the Go service. The Compose stack runs a `caddy` container that owns 80/443, obtains certificates and reverse-proxies to `wallpaper-api:8080`; validate Caddyfile changes with `docker run --rm -v <file>:/etc/caddy/Caddyfile:ro caddy:2-alpine caddy validate --config /etc/caddy/Caddyfile`.

All three survive a `git pull`, so do not expect them in the repo.
  - The host Caddy and the legacy `wallpaper-api` systemd unit are stopped. Both remain `enabled`, so after a reboot they will start again: host Caddy will race the `wallpaper-caddy` container for 80/443, and the legacy service will listen on `127.0.0.1:8080`. The agent is not allowed to change enable state; the user must run `systemctl disable caddy wallpaper-api` to make the setup reboot-safe.
  - `/etc/caddy/Caddyfile` on the host is generated by `packaging/server/provision.sh`, which overwrites manual edits. Now that the container owns those ports, re-running that provisioning would also put the host Caddy back in conflict with the container.
  - Adding wallpapers in production: push image files into the `images/` directory of the GitHub repository `MinimaxFlora/WallpaperHub`. A GitHub Actions workflow regenerates and commits `manifest.json`; the service picks it up within `WALLPAPER_MANIFEST_REFRESH_INTERVAL` (default 15m), with no restart or redeploy. Image bytes are fetched from GitHub on first request and then served from the local disk cache.
  - Wallpaper files use two-digit sequential names (`01.webp`, `02.webp`, ...) in the order they were added, so lexicographic ordering matches insertion order and the rotation stays predictable.
  - Legacy (no longer used) redeploy procedure: cross-compile locally with `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w"`, upload the binary to `/opt/wallpaper-api/wallpaper-api`, then `systemctl restart wallpaper-api`.
  - The VPS sshd closes rapid successive connections with `kex_exchange_identification: Connection closed by remote host`; retry after a pause and reuse one connection via `ssh -o ControlMaster=auto -o ControlPath=<sock> -o ControlPersist=600` for the rest of the session.
